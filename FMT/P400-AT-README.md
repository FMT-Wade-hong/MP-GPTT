# P400 DATA / AT integration

Current-page editable-register audit (manual pp.105–116): S102 (0–14), S110 (1–10), S116 (0–254 conservative intersection), S128 (0–2), S142 (0–3), FH S150 (0–2), S151 (100–65000), S153 (0/1), S213 (0–254), S217 (0–2), NB S125 (0–2), S131/S132 (0–63) are now editable when the returned value is recognized. Existing numeric settings and masked S107 remain editable. S123/S124 are measurements; S154 is undocumented and remains read-only. Unknown composite responses remain read-only rather than guessing a writable value. NB channel choices must correspond to the dealer-configured table and allowed direction; NB bandwidth must match that table and modulation/link rate. S128/S142 changes require a separate batch and may interrupt communication; unsupported factory options are not enabled automatically.

S102/S110 writes require user-confirmed CONFIG-forced command mode at 9600/8N1 (manual pp.37,105,107). The command connection stays at these temporary settings until ATA; on return to DATA the peer/PC must use the newly configured S102/S110. The application closes the port after ATA and reports the new settings instead of silently reconnecting. No hardware was exercised for this audit.

S107 is editable through a masked password dialog in the New Value column. No password is prefilled; an empty dialog removes the pending change (it does not clear the modem password). The current implementation accepts 1–16 ASCII letters, digits, underscore, dot or hyphen. Confirmation and protocol errors redact the value. S107 writes use command acknowledgement and AT&W acknowledgement only: masked readback cannot verify the password or detect concurrent password changes. Verify matching peer communication on the ground after updating.

The third tab, 頻率表／10 組合, is an offline 50-row frequency editor (MHz, six decimal places). Ten local slots each store a user-defined name and 50 entries, including blanks. Select a slot and explicitly load or save it; selecting alone does not replace the draft. Slots reside in the application's user-data directory under `P400FrequencyPlans/slot-01.json` through `slot-10.json`. Overwriting keeps the previous version as `.bak`.

Import accepts exported CSV (`Channel,FrequencyMHz`), JSON slot files, one frequency per line, and numbered two-column text/AT tables. Clipboard paste supports the same text formats. CSV exports all 50 numbered rows; slot names are saved in JSON, not CSV. Invalid imports are rejected before changing the draft. Save or export before closing the page; drafts are not automatically persisted. The first tab's frequency readback can be explicitly copied into the editor with 帶入最近模組讀回.

The third tab also has explicit module read/write buttons and an ATP0 primary / ATP1 secondary selector. First connect in the DATA/AT tab. Writing requires all 50 values, 410–480 MHz, fresh S128=2 and S238=1, and no uncertain prior writes. After confirmation the original table is backed up under `P400FrequencyPlans/backups`. A fresh comparison detects changes since confirmation. Manual pp.76–78 specify `ATP0=` / `ATP1=` followed by 50 CR/LF-terminated frequency lines, with automatic table saving and a completion OK. The selected table is then read back and all 50 values compared. No AT&W or other-table write is sent. A failure quarantines the connection: changes may already be saved; release/reconnect and inspect before proceeding. There is no automatic rollback or peer synchronization. Both tables must be populated for operation; writing one does not populate the other. NB dealer-table writes are not supported. Frequency range checks do not establish regulatory or device-specific authorization.

No predefined frequency combinations are supplied. Run `FMT/Test-P400Frequency.ps1` for local editor tests and `FMT/Test-P400FrequencyRadio.ps1` for simulated transfer, readback, refusal, timeout, mode and cancellation tests. Actual firmware/serial behavior still requires ground bench verification.

Source: user-provided P400_Manual.v1.33.pdf, pp.37–38, 104–115, 125.

Open Initial Setup → P400 數傳設定. Select the DATA COM port and matching baud rate (8N1). No automatic connection occurs. Disconnect telemetry and other serial applications first. Entering command mode interrupts radio traffic; only operate on the ground.

The normal entry sequence uses 1.1-second transmit guard intervals around `+++` (no carriage return), then `AT` and `ATI1`. For a module already forced into command mode with CONFIG, select the existing-command-mode checkbox and the appropriate baud (normally 9600). Only a P400 product response enables settings.

Read operations: `AT&V`, selected S registers, register help, and `ATP0?`. Editable fields are a conservative subset of common numeric settings, filtered by S128 mode. New firmware values outside this subset remain visible and read-only. Serial baud/format, modem type, NB bandwidth and frequency channel selection are read-only in this version. It does not edit dealer frequency tables, factory options, AES, or firmware. PicoConfig remains available on the backup tab after releasing this page's COM port.

Writes require an explicit difference confirmation. All changed values are range-checked and compared to fresh original values before writing. Each set is read back, and only then is `AT&W` sent. Failed or uncertain writes are not rolled back automatically; settings may already have changed in RAM. A save acknowledgement does not prove retention after a power cycle. Peers are not modified automatically.

“返回 DATA 並釋放” explicitly sends `ATA`; the UI reports it as sent, not confirmed RF connectivity. “僅釋放序列埠”, page departure, cancellation, and disposal close the port without sending `ATA` or saving. The modem may remain in AT mode. Re-enter as already in command mode, or recover according to the hardware manual. Do not resume flying until telemetry and settings are verified.

Verification: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File FMT/Test-P400At.ps1`. Simulated transport covers successful saving, rejected writes, mismatched readbacks, wrong product, timeout, cancellation, telemetry guard, range validation and page construction. No real P400 was connected during implementation; firmware response framing and actual serial/RF behaviour still require bench verification.
