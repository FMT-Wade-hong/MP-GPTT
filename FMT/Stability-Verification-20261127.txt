本機錯誤紀錄與修正

1. 設定檔占用造成啟動失敗。
   crash.log 在 11/12、11/23、11/25 記錄 Settings.Save → EnsureDefaults 的 IOException。
   設定改為先序列化完整 XML，再以同目錄暫存檔原子替換；讀寫使用依路徑區分的
   跨程序鎖，短暫分享衝突會有限次重試。沒有變更的啟動預設值不再重複存檔。
   持續占用仍明確回報失敗，保留原設定並清理此次暫存檔，不假報儲存成功。
   同時開啟多份程式仍採最後一次成功存檔的內容，不合併各程序的個別設定變更。

2. 切換 3D 地圖時 OpenGL context 失效。
   11/24 的堆疊為 OpenGLtest2.test_Resize → OnLoad → 面板顯示切換，錯誤代碼 6。
   載入／縮放／繪圖加入有效狀態檢查與失效通知；失效後停止重複繪圖並回到 2D。
   再次開啟 3D 時建立新控制項，避免重用失效狀態；重複 Load 不再啟動多個載圖執行緒。
   關閉時停止計時器及背景載圖、釋放圖形資源與地圖快取；背景 GL 視窗由所屬執行緒釋放。
   不再從 finalizer 執行 OpenGL 清理，重新建立 context 時重新核對 shader program。

3. FTP 目錄讀取完成後存取已關閉的控制項。
   10/29 日誌記錄 MavFTPUI.PopulateTreeView → 已釋放 TreeView 的例外；目前原碼仍有該路徑。
   視窗關閉會取消目錄讀取，await 返回及排入佇列的進度更新均檢查視窗狀態。
   重複刷新合併，過期的資料夾導覽結果不再覆寫後來選擇。
   此修正涵蓋目錄讀取／刷新／導覽；未宣稱所有 FTP 上傳下載操作均已重寫。

驗證方式

- 建置 Release 成功：0 errors、1270 warnings，保留建置紀錄。
- 新增 Test-StabilityLifecycle.ps1：四個程序各存檔 80 次，同時以正式 Load 讀取，
  檢查完整 XML、分享鎖重試、持續占用保留舊檔及啟動不做多餘存檔。
- 10 個真實 GL 控制項、100 次顯示／縮放／重新 Load，包含無 handle、零尺寸、
  注入 GraphicsContextException、通知去重及關閉後背景執行緒停止。
  這是實際 GL context 生命週期加受控例外注入，不是重現特定顯示驅動故障。
- 實際 FlightData 控制項另做 5 次失效通知／退回 2D／重新開啟 3D，核對選項狀態、
  面板收合及失效控制項被釋放並替換。測試不啟動 FlightData 遙測工作。
- 10 個 FTP 視窗，以記憶體 MAVLink 回覆空目錄，測試正常讀取、重複刷新，
  以及根目錄／子資料夾讀取中關閉。啟用跨執行緒控制項存取檢查；沒有檔案變更命令。
- 正常 GC 的連續測試反覆 GDI／OpenGL HUD 繪圖、縮放、擷取、模式列縮放與 ICE 頁面開關。
  不在採樣前強制 GC，因此記憶體包含尚未回收的配置，不能當成全數留存量。

測試環境曾遇到的問題

- 首次完整回歸的 ReleaseVersion 共用預覽存圖與同時啟動的連續測試撞檔，
  Test-RoverChinese.ps1 的 Bitmap.Save 回報 GDI+ 錯誤；已分開重跑通過並保留首次結果。
- FTP 測試使用手動 Application.DoEvents，初版測試未安裝 WinForms SynchronizationContext，
  導致 await 返回非 UI 執行緒；補上正式 UI 的同步環境後，開啟跨執行緒檢查再驗證。
  此項是測試環境修正，不當作產品缺陷或產品修復成果。
- GL 故障注入需等待非忙碌的縮放嘗試，因產品在繪圖資源忙碌時會跳過當次縮放；
  未顯示的主頁測試也需明確建立通知 handle。初版測試的時序／handle 假設已調整，
  診斷紀錄保留在 lifecycle-with-fallback*.log、lifecycle-diagnostic.log。
